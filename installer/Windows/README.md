# KonomiTV Windows インストーラー (Inno Setup 製)

従来の CLI ベースのインストーラー (`KonomiTV-Installer.exe`) に代わる、**Windows 専用のウィザード形式インストーラー**です。
「よくある MSI インストーラー」のように、Next を押しながら進んでいくだけで KonomiTV をインストールできます。

## 概要

- **成果物**: `KonomiTV-Setup-<バージョン>.exe` (Inno Setup 製の単一実行ファイル)
- **対応OS**: Windows 10 / 11 (x64) のみ
- **方針**: 設定入力を最小限に抑え、バックエンド (EDCB / Mirakurun) とエンコーダーは**自動検出**する
- **インストール本体**: 同梱のインストールエンジン (`KonomiTV-Installer-Engine.exe`) が、既存の Python インストールロジックを**無人モード**で実行する

## アーキテクチャ

```
┌───────────────────────────────┐
│  KonomiTV-Setup-<version>.exe │  Inno Setup 製ウィザード (このフォルダの KonomiTV-Setup.iss)
│  ┌─────────────────────────┐  │
│  │ KonomiTV-Installer-     │  │  インストールエンジン (PyInstaller 製 exe、{tmp} に展開)
│  │ Engine.exe              │  │  ─ バックエンド自動検出 (--detect-backend <IP>)
│  └─────────────────────────┘  │  ─ エンコーダー自動検出 (--detect-encoder)
└──────────────┬────────────────┘  ─ 無人インストール (--install)
               │ 進捗ファイル (key=value のログ) をポーリング
               ▼
    既存の Python インストールロジック (installer/Installer.py)
```

ウィザードが集めた設定を一時ファイルに書き出し、エンジンを `--install` モードで実行します。
エンジンは進捗をファイルに書き込み、ウィザード側がポーリングして進捗バーとログを表示します。
ダウンロードや依存パッケージの導入など、**インストール処理自体は既存の `Installer.py` をそのまま利用**しています。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `KonomiTV-Setup.iss` | Inno Setup スクリプト (ウィザード UI の定義) |
| `../KonomiTV-Installer-Engine.spec` | インストールエンジン用の PyInstaller spec |
| `../WindowsInstaller.py` | エンジンの実装 (自動検出・無人インストール) |
| `../KonomiTV-Installer.py` | エンジンモードの CLI エントリポイント |
| `../Installer.py` | 既存のインストールロジック (無人モード対応済み) |
| `../Utils.py` | 共通ユーティリティ (エンコーダー自動判定・進捗レポーター) |

## ビルド方法

```powershell
# 1. インストールエンジンを PyInstaller でビルド
cd installer
poetry run task build-engine   # → dist/KonomiTV-Installer-Engine.exe

# 2. Inno Setup でウィザードをビルド (要: Inno Setup 6.4 以降 / 7 インストール済み)
& "C:\Program Files\Inno Setup 7\ISCC.exe" "Windows\KonomiTV-Setup.iss"
# → dist/KonomiTV-Setup-<バージョン>.exe
```

CI (`build_installer.yaml`) では上記の2ステップを自動実行し、`KonomiTV-Setup-<バージョン>.exe` を GitHub Releases に公開します。

## ウィザードの流れ

| ページ | 内容 |
|---|---|
| ようこそ | KonomiTV のインストールウィザードの開始 |
| ライセンス | MIT ライセンスへの同意 (「同意する」を押すまで次へ進めない) |
| インストール先 | 既定 `C:\KonomiTV` |
| バックエンド | IP アドレス入力 → 「検出」ボタンで自動検出 (EDCB: `tcp://<IP>:4510` / Mirakurun: `http://<IP>:40772`)。検出中は経過秒数 (確認中...（X s）) を表示し、検出結果を自動選択。**バックエンドが検出されるまで次へ進めない** (IP を変更した場合は再検出が必要) |
| エンコーダー | GPU を自動判定して推奨を初期選択 (FFmpeg / QSVEncC / NVEncC / VCEEncC)。検出結果は「推奨: エンコーダー名 (GPU: GPU名)」の形式で表示 |
| フォルダ | 録画フォルダとキャプチャフォルダをそれぞれ設定 (最低1つずつ必須)。パス入力 + 「参照...」ボタンでフォルダ選択ダイアログを開き、「追加」/「削除」ボタンでリストを管理 (複数指定可)。存在しないパスや相対パスはエラー表示 |
| サービスアカウント | 実行ユーザー名 (既定: 現在のユーザー) + パスワード |
| インストール | 進捗バー + ログ表示 |
| 完了 | ブラウザで開く |

### 削減した入力

- **バックエンド URL / エンコーダー**: 自動検出。カスタムポート等は後から設定画面で変更できます

## 上書きインストール

既存の KonomiTV がインストールされているフォルダを選択した場合は、**必ず確認を取ってから上書きインストール**します。
上書き時は `config.yaml`・`server/.venv`・`server/data`・`server/logs` を保持し、ソースコードとサードパーティーライブラリを更新します (`Installer.py` のインストール先フォルダ準備処理が担当)。

### アンインストーラー関連ファイルの扱い

Inno Setup はインストール開始時にインストール先フォルダへアンインストーラー (`unins000.exe` / `unins000.dat` / `unins000.msg`) を自動で作成するため、インストール先フォルダの既存ファイルを検査する際はこれらを「KonomiTV 以外のファイル」と誤判定しないよう、**常に除外**しています。

- ウィザード側 (`KonomiTV-Setup.iss` の `IsDirEmpty`): アンインストーラー関連ファイルのみが存在するフォルダは「実質的に空」として扱い、警告なしでインストールを続行する
- エンジン側 (`Installer.py` の `inno_setup_uninstaller_files`): アンインストーラー関連ファイルのみが存在するフォルダは「実質的に空」として扱い、上書きインストールを続行する
- アンインストール時の検査 (`KonomiTV-Setup.iss` の `HasForeignFiles`): フォルダごと削除の確認時にアンインストーラー関連ファイルを除外する

アンインストーラーは削除するとアンインストールできなくなるため、上書きインストール時は一時退避してインストール完了後に元の場所へ戻しています。

> アップデート (設定の差分適用など) は現時点では未対応です。既存環境のアップデートは従来の CLI インストーラーを利用してください。

## アンインストール

「プログラムと機能」からアンインストールできます。アンインストーラーは Windows サービスの停止・削除と、ファイアウォールの受信規則の削除も行います。

## 自動検出・進捗連携の仕組み

エンジンとウィザードは、**key=value 形式のテキストファイル**で連携します (JSON パーサーを Pascal に実装する手間を避けるため)。

- **自動検出**: エンジンの `--detect-backend` / `--detect-encoder` が結果を `--output-file` に書き出し、ウィザードが読み込んでラジオボタン等に反映します
- **検出中の表示**: バックエンドの自動検出はエンジン実行中も `SetTimer` のタイマーで経過秒数をカウントし、ラベルに「確認中...（X s）」と表示します (インストール進捗と同じ仕組み。検出中はナビゲーションを無効化します)
- **進捗**: エンジンが `[STEP]` / `[PROGRESS]` / `[DONE]` / `[ERROR]` 行を進捗ファイルに追記し、ウィザード側が **`SetTimer` のタイマー**でポーリングして表示します。標準のインストールページに「現在の処理 (ステップ) ラベル → 標準のプログレスバー (進捗率) → ログ表示」の順に配置し、`[STEP]` は現在の処理ラベルとログ、`[PROGRESS]` はプログレスバーに反映します
  - `[PROGRESS]` は**全体進捗率 (0〜100) を小数点付きの小数 (例: `23.4`) で書き出します**。エンジン側 (`Utils.py` の `ProgressFileReporter`) がステップごとに「残りの区間の 20%」を割り当てるため、ステップ数が事前に分からなくてもバーが必ず動き続けます (`[STEP]` のたびにステップ開始位置まで前進し、ダウンロードなどの細かい進捗はそのステップ内で更新。`[DONE]` で 100% になります)
  - ウィザード側は `[PROGRESS]` の値を**小数点以下の桁を切り捨てて**プログレスバーに反映します (`StrToIntDef` は小数点付き文字列を解析できず常に 0 になるため、小数には直接使えない)
- **設定ファイル**: ウィザードが集めた設定値を UTF-8 の key=value ファイル (`SaveStringsToUTF8FileWithoutBOM`) で書き出し、エンジンが読み込んでインストールを実行します (パスワードの日本語などにも対応)
- **エンコーディング**: エンジンとのファイル連携はすべて UTF-8。`LoadStringsFromFile` は BOM なし UTF-8 に対応しているためそのまま読み込めます (Inno Setup 6.4 以降が必要)

## 注意点

- インストールエンジンは PyInstaller 製のため、**ウイルス対策ソフトに誤検知される可能性があります** (従来のインストーラーと同様)
- インストーラーの実行には管理者権限が必要です (Inno Setup が UAC で昇格します)
